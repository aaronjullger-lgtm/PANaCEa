# Skill Routing Matrix

| Request type | Primary skill | Optional secondary skill | Avoid when |
| --- | --- | --- | --- |
| Choose a skill, optimize skill usage, audit `.agents/skills`, resolve overlapping triggers | `skill-routing-and-usage` | `skill-creator` when creating or editing skills | The request clearly names one already-selected skill and only asks to run it |
| Any unclear StudyPANaCEa repo work, architecture tracing, file ownership, feature placement | `panacea-navigator` | Narrower `panacea-*` skill after the affected area is identified | The request is purely personal decision support or unrelated to this repo |
| Frontend redesign, landing page, dashboard UI, visual polish, AIDesigner workflow | `aidesigner-frontend` for AIDesigner-driven work; otherwise `panacea-view-composition` | `panacea-dashboard-analytics` for metric correctness; `performance-audit-optimise` for heavy UI | The task is backend-only |
| PANaCEa route registry, app views, lazy components, navigation, shell layout, protected routes | `panacea-view-composition` | `aidesigner-frontend` for visual generation; `panacea-verify` for route checks | The task only changes data calculations |
| PANaCEa clinical content, refinery, ingestion, enrichment, citations, AI question generation | `panacea-content-refinery` | `ai-agent-design-and-eval` for agent architecture; `security-and-privacy-audit` for sensitive content handling | The task only changes UI layout |
| PANaCEa dashboards, readiness analytics, progress metrics, charts, daily prescriptions | `panacea-dashboard-analytics` | `panacea-prisma-data-integrity` for source data; `panacea-verify` for targeted checks | The task is generic product strategy |
| PANaCEa Cloudflare Pages Functions, endpoint middleware, auth wrappers, env access, CORS, rate limits | `panacea-edge-endpoints` | `security-and-privacy-audit`; `api-database-audit-and-fix`; `supabase` if Supabase-specific | The task concerns local Express-only development |
| PANaCEa FSRS, implicit ratings, retrievability, review scheduling, MVRT, Ghost Grader | `panacea-fsrs-guardrails` | `spaced-repetition-scheduler-improve` for algorithm redesign; `panacea-session-pipeline` for answer submission flow | The task is general calendar scheduling |
| PANaCEa study sessions, QuizView, drills, answer submission, syncManager, telemetry | `panacea-session-pipeline` | `panacea-fsrs-guardrails`; `panacea-offline-sync`; `panacea-verify` | The task is static content editing |
| PANaCEa offline-first behavior, PWA cache, sync queues, retry, idempotency, stale data | `panacea-offline-sync` | `panacea-session-pipeline`; `debug-reproduce-isolate` for data-loss bugs | The task is online-only dashboard presentation |
| PANaCEa OSCE, virtual patients, SOAP notes, station flow, rubrics, AI clinical simulation | `panacea-osce-simulation` | `ai-agent-design-and-eval`; `security-and-privacy-audit` for safety/privacy | The task is unrelated to OSCE or simulation |
| PANaCEa Prisma schema, migrations, Postgres integrity, ReviewLog, QuestionAttempt, production-like data scripts | `panacea-prisma-data-integrity` | `supabase`; `security-and-privacy-audit`; `api-database-audit-and-fix` | The task only reads mock frontend data |
| PANaCEa verification, tests, validation selection, check summaries | `panacea-verify` | The primary domain skill for the changed area | The user only asks conceptual questions |
| Initial repo audit, architecture map, project standards, dev command docs | `repo-operating-system` | `security-and-privacy-audit` for auth/secrets boundaries | A feature or bug fix is already scoped |
| Add tests, improve regression coverage, create safety net | `setup-testing-safety-net` | `debug-reproduce-isolate` when tests target a known bug | The user only asks to run existing tests |
| Bug, crash, failing test, unexpected behavior, reproduction | `debug-reproduce-isolate` | Domain skill for the failing area | The request is broad product ideation rather than a defect |
| API, database, Supabase connection, RLS, migrations, inconsistent data | `api-database-audit-and-fix` | `supabase` for Supabase-specific products and CLI work; `security-and-privacy-audit` for authorization risk | The request only asks for frontend UI work |
| GitHub Actions, CI failure, slow pipeline, deploy automation | `optimize-ci-cd` | `release-readiness` when production release gates are involved | The request is only local test setup |
| Security audit, privacy review, auth, secrets, authorization, payment webhooks | `security-and-privacy-audit` | `api-database-audit-and-fix` for endpoint or RLS fixes | The request is a non-sensitive performance or product review |
| Slow page, heavy dashboard, Core Web Vitals, bundle size, latency | `performance-audit-optimise` | `api-database-audit-and-fix` for query latency; frontend/UI skills when changing UI | The request is about CI speed only |
| Review queues, FSRS, SM-2, retention, due dates, readiness scheduling | `spaced-repetition-scheduler-improve` | `setup-testing-safety-net` for scheduler edge-case tests | The request is general calendar scheduling with no spaced-repetition behavior |
| Tutor, question generator, AI agent, evals, prompts, tool calling | `ai-agent-design-and-eval` | `security-and-privacy-audit` for privacy or unsafe output; `setup-testing-safety-net` for eval harnesses | The request only asks for static content |
| Roadmap, feature brainstorming, product sprint, prioritization | `product-improvement-planner` | `performance-audit-optimise` or `security-and-privacy-audit` when findings drive prioritization | The request is already a concrete implementation task |
| Release, launch, production deploy, ship checklist, release notes | `release-readiness` | `optimize-ci-cd`, `security-and-privacy-audit`, or `performance-audit-optimise` for release blockers | The request is only a development preview |
| Post-launch monitoring, incidents, runbooks, postmortems | `post-launch-monitoring-and-response` | `debug-reproduce-isolate` during active incident root-cause work | The request is pre-release readiness |
| Any task involving Supabase products, SSR auth, Supabase CLI, RLS, storage, realtime, vectors | `supabase` if Supabase is the main task; otherwise secondary | `api-database-audit-and-fix` or `security-and-privacy-audit` for broader workflow | Supabase is only mentioned as historical context |
| Personal decision support or prioritization outside repo execution | `think` | None | The request asks for code or repository edits |
| End a session, save progress, write handoff, commit/push when requested | `wrap-up` | Release or verification skill if the session ends near a ship point | The task is still actively being implemented |
| Audit and clean stale files, dead code, duplicate pathways | `panacea-repo-hygiene` | `repo-operating-system`, `panacea-verify` | The task is active feature development |
| Sequence multi-agent work, resolve conflicts, plan cross-skill sprints | `panacea-syncytium-coordinator` | `panacea-navigator`, `panacea-verify` | The task has one clear owner |
| Write regression tests, hunt regressions, fill test gaps | `panacea-regression-guard` | `panacea-verify`, `vitest-author` | The user only asks to run existing tests |
| Generate AI questions, work on generation pipeline, batch refill | `panacea-question-generation` | `panacea-content-refinery`, `panacea-edge-endpoints`, `panacea-verify` | The task is UI-only |
| Design/run identity or condition/content schema migration | `panacea-identity-migration` | `panacea-prisma-data-integrity`, `panacea-verify` | No database migration is involved |
| Deploy or configure Cloudflare/Wrangler/KV/production build | `panacea-deployment-guard` | `release-readiness`, `security-and-privacy-audit`, `panacea-verify` | The task is local dev only |
| Audit medical content correctness, drug data, condition metadata | `panacea-clinical-content-auditor` | `panacea-content-refinery`, `panacea-prisma-data-integrity` | The request is about generating new questions |
| Audit Clerk auth, RBAC, tokens, or endpoint protection | `panacea-auth-guard` | `security-and-privacy-audit`, `panacea-edge-endpoints` | The task is about FSRS algorithm logic |
| Fix study plan generation or daily plan endpoints | `panacea-study-plan` | `panacea-fsrs-guardrails`, `panacea-dashboard-analytics`, `panacea-session-pipeline` | The request is a general strategy discussion |
| Audit RAG, vector search, embeddings, chunking, or source attribution | `rag-quality` | `hybrid-retrieval`, `memory-regression-eval`, `memory-safety` | The task is pure database schema changes |
| Review memory ingestion, prompt context, retention/deletion, privacy | `memory-safety` | `memory-discovery`, `security-and-privacy-audit` | The task is purely frontend UI work |
| Work on entity/relation extraction, knowledge graph, GraphRAG | `graph-memory` | `memory-regression-eval`, `panacea-prisma-data-integrity`, `panacea-verify` | The task only uses vector search |
| Review SQL-backed memory, learner progress, FSRS state | `tabular-memory` | `memory-safety`, `panacea-prisma-data-integrity`, `panacea-verify` | Writing without database schema review |
| Combine vector, keyword, graph, table, cached memory | `hybrid-retrieval` | `rag-quality`, `memory-regression-eval`, `memory-safety` | Only one retrieval method is in play |
| Audit/review RAG, vector memory, graph memory, agent memory, retrieval routing | `memory-discovery` | `rag-quality`, `memory-safety`, `tabular-memory` | The task explicitly names one storage layer with no routing concerns |
| Add/run memory evals, golden queries, retrieval regression tests | `memory-regression-eval` | `rag-quality`, `graph-memory`, `tabular-memory`, `panacea-verify` | Memory was not modified |
