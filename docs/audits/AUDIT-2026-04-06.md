## Part 1: Gemini API Migration Recommendations

### Step 1 — Migration Criteria Framework

Before evaluating specific files, these are the criteria that determine whether a Gemini call should migrate:

| Criterion | Favors Gemini | Favors Claude | Favors OpenAI | Favors DeepSeek |
|-----------|--------------|---------------|---------------|-----------------|
| **Medical reasoning quality** | Good | Best-in-class for clinical nuance | Good | Untested for clinical |
| **Structured JSON output** | Native JSON mode | Tool use + JSON mode | json_object mode | JSON mode |
| **Cost per token** | Flash = cheapest | Haiku competitive; Sonnet 2-3× Flash | GPT-4o-mini competitive | Cheapest generation |
| **Embedding cost** | text-embedding-005 free tier | No embedding model | text-embedding-3-small ($0.02/1M) | Limited embedding offering |
| **Context window** | 1M (Pro), 1M (Flash) | 200K (Sonnet) | 128K (GPT-4o) | 128K |
| **Edge/Worker compat** | REST API works | REST API works | REST API works | REST API works |
| **Streaming SSE** | Native | Native | Native | Native |
| **Existing integration depth** | Deep (SDK + REST + Edge) | None | None | None |
| **768-dim embedding compat** | ✅ Native | N/A | ❌ 1536-dim (requires re-index) | ❌ |

**Key insight:** Migration should target **high-value reasoning tasks** (clinical feedback, MCQ generation) where Claude's medical reasoning advantage justifies the integration cost. Embeddings and low-latency classification should stay on Gemini.

| `functions/api/gemini/stream.ts` | General chat/tutoring streaming | `gemini-2.0-flash` | **Evaluate Further** | If this powers the Virtual Preceptor's conversational interface, Claude Haiku via streaming would provide better clinical reasoning at comparable cost. | `functions/api/gemini/index.ts` | Synchronous generation proxy | `gemini-2.0-flash` | **Evaluate Further** | Same as above — depends on downstream usage. If primarily for clinical explanations, Claude migration adds value. |
| `guidelineRagService.ts` | RAG retrieval (no generation) | `text-embedding-005` | **Keep Gemini** | This file only does retrieval (pgvector + FTS), not generation. The embeddings feed into a prompt that's sent elsewhere. Keep the retrieval on Gemini embeddings; consider Claude for the generation step that consumes these snippets. |

| `scripts/addNewConditions.ts` | Medical condition content | `gemini-2.5-pro` | **Migrate to Claude** | Generating 13-field medical condition records (diagnostics, treatment, complications, prognosis) for 100+ conditions requires deep clinical knowledge. Claude's medical reasoning advantage matters here. One-time migration cost. |
| `scripts/addNewTreatments.ts` | Treatment content generation | `gemini-2.5-pro` | **Migrate to Claude** | Treatment content directly impacts what students learn. Claude's structured output via tool use produces more reliable JSON than Gemini's JSON mode for complex medical schemas. |
| `scripts/audit-question-quality.ts` | Question quality audit | `gemini-2.0-flash` | **Migrate to Claude** | Evaluating whether vignettes leak diagnoses, checking pertinent negatives, and validating structured rationales is a nuanced clinical reasoning task. | `scripts/assess-content-adequacy.ts` | Content assessment + regen | `gemini-2.5-flash` | **Keep Gemini** | This is primarily metric-based (word counts, field presence, completeness scoring). The "intelligence" is in the scoring rubric, not the LLM call. Flash is adequate and cheaper. |

## Requires Design Decision

### 1. Claude API Migration Scope
**Decision:** Which Gemini→Claude migrations to prioritize?
- **Option A (Conservative):** Migrate only batch scripts (lab content, conditions, treatments, question audit) — low risk, high clinical quality gain, ~2 days effort.
- **Option B (Moderate):** Option A + add Claude as an alternative provider in the streaming proxy for Virtual Preceptor sessions — ~1 week effort, requires provider abstraction in `geminiService.ts`.
- **Option C (Aggressive):** Full multi-provider architecture with routing rules (Claude for clinical reasoning, Gemini for speed/cost, DeepSeek for bulk classification) — ~2-3 weeks effort.
- **Recommendation:** Start with Option A. Build provider abstraction during Option A work. Evaluate Option B after measuring clinical feedback quality delta.

### 2. TanStack Query Migration Strategy
**Decision:** Incremental vs. big-bang migration of ~301 fetch() calls?
- All 301 calls currently work. Migration improves caching, deduplication, and offline support but requires touching many files.
- **Recommendation:** Incremental. Migrate `conditionSearch.ts` first (4 hooks), then tackle component-level fetches grouped by feature area during sprint work.

### 3. Adaptive Thresholds vs. Static Thresholds
**Decision:** Should calibration quadrants, fluency scoring, and implicit metrics use AI-driven adaptive thresholds?
- **Pro:** Personalized learning experience, better FSRS accuracy for diverse learner profiles.
- **Con:** Adds latency (LLM call per classification), cost per session, and debugging complexity. Current static thresholds are pedagogically sound.
- **Recommendation:** Start with embedding-based learner clustering (no LLM latency cost). Use cluster membership to select from 3-4 pre-computed threshold profiles rather than real-time LLM calls. Revisit full LLM personalization once you have usage data showing threshold miscalibration.

### 4. Express Route Migration Priority
**Decision:** Which P0 routes to port first given limited sprint capacity?
- `/api/questions/*` (11 endpoints) — blocks main session flow on Edge
- `/api/content/*` (4 endpoints) — blocks clinical library on Edge
- `/api/osce/*` (5 endpoints) — blocks OSCE simulation on Edge
- **Recommendation:** Questions first (highest traffic), then Content (dependency for library), then OSCE (complex Gemini streaming integration — save for dedicated sprint).

### 5. Embedding Provider Lock-in
**Decision:** Should you maintain `text-embedding-005` (768-dim) or plan migration to a different embedding model?
- Current pgvector HNSW index is built on 768-dim vectors. ANY dimension change requires re-embedding all MedicalContent records.
- `text-embedding-005` quality is adequate for medical content search.
- **Recommendation:** Keep `text-embedding-005` for now. If search quality degrades as content grows, evaluate `text-embedding-3-small` (OpenAI, 1536-dim) but plan a dedicated re-indexing sprint.
