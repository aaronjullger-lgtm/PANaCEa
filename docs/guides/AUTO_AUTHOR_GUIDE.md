# Auto-Author Pipeline

## Overview

The Auto-Author pipeline automatically generates AI content for medical conditions that are missing core educational data in the database. It uses Google Gemini to create high-quality, PANCE-focused study material.

## Architecture

### Components

1. **Content Generator** (`lib/services/autoAuthor/contentGenerator.ts`)
   - Handles AI generation via Gemini API
   - Constructs prompts with clinical accuracy requirements
   - Includes retry logic and error handling

2. **Database Service** (`lib/services/autoAuthor/databaseService.ts`)
   - Identifies conditions missing content
   - Saves generated content to Prisma database
   - Merges with existing content (preserves manually-added fields)

3. **Main Orchestrator** (`lib/services/autoAuthor/index.ts`)
   - Coordinates the full pipeline
   - Provides progress tracking and statistics
   - Handles rate limiting

4. **Runner Script** (`scripts/generateMissingContent.ts`)
   - CLI interface for the pipeline
   - Command-line argument parsing
   - Environment variable configuration

## Content Structure

```typescript
interface GeneratedConditionContent {
  // Core fields (always generated)
  overview: string;
  clinicalPearls: string[];
  symptoms: string[];
  riskFactors: string[];
  diagnosis: string;
  treatment: string;

  // Extended fields (optional)
  etiologyPathophysiology?: string;
  epidemiology?: string;
  examFindings?: string[];
  complications?: string[];
  prognosis?: string;
  differentialDiagnosis?: string[];
}
```

## Usage

### Basic Usage

```bash
# Generate content for up to 100 conditions
npm run generate:missing-content

# Or directly with tsx
tsx scripts/generateMissingContent.ts
```

### Command-Line Options

```bash
# Dry run (see what would be processed)
tsx scripts/generateMissingContent.ts --dry-run

# Process only 50 conditions
tsx scripts/generateMissingContent.ts --max-conditions=50

# Increase delay between API calls (for rate limiting)
tsx scripts/generateMissingContent.ts --delay=3000

# Include extended fields (epidemiology, complications, etc.)
tsx scripts/generateMissingContent.ts --extended

# Combine options
tsx scripts/generateMissingContent.ts --max-conditions=25 --extended --dry-run
```

### Environment Variables

**Required:**

- `GEMINI_API_KEY` or `GOOGLE_API_KEY` - Your Google Gemini API key

**Optional:**

- `DATABASE_URL` - PostgreSQL connection string (Prisma)
- `DIRECT_DATABASE_URL` - Direct database URL for migrations

## Workflow

### 1. Condition Detection

The pipeline identifies conditions missing content by checking for:

- No `content` field at all
- Missing `overview`, `symptoms`, or `diagnosis`
- Empty arrays in required fields

### 2. Content Generation

For each missing condition:

- Constructs a PANCE-focused prompt with clinical requirements
- Calls Gemini API with retry logic (up to 3 attempts)
- Validates generated JSON structure
- Ensures required fields are present

### 3. Database Storage

Generated content is merged with existing data:

- **Preserved**: Any manually-added fields or custom content
- **Updated**: Only the fields generated by AI
- **No Overwrite**: Existing content is never deleted

### 4. Progress Tracking

The pipeline provides real-time feedback:

```
[15/100] Acute Coronary Syndrome (CV)
   ✅ Generated and saved successfully

[16/100] Atrial Fibrillation (CV)
   ❌ Generation failed: API rate limit exceeded
```

## Error Handling

### Common Errors

1. **Missing API Key**

   ```
   ❌ Error: GEMINI_API_KEY or GOOGLE_API_KEY environment variable is required
   ```

   **Solution**: Set `export GEMINI_API_KEY=your_key`

2. **Rate Limiting**

   ```
   ❌ Generation failed: 429 Resource Exhausted
   ```

   **Solution**: Increase `--delay` or reduce `--max-conditions`

3. **Invalid JSON Response**
   ```
   ❌ Generation failed: Missing required fields in generated content
   ```
   **Solution**: AI occasionally returns malformed JSON; script retries automatically

### Recovery

Failed conditions are logged but don't stop the pipeline:

```
⚠️  Errors:
   1. Subarachnoid Hemorrhage: API rate limit exceeded
   2. Meningitis: Invalid JSON response
```

Re-run the script to retry failed conditions.

## Performance

### Rate Limiting

- **Default**: 2000ms (2 seconds) between API calls
- **Recommended**: 2000-3000ms for sustained generation
- **Aggressive**: 1000ms (may hit rate limits)

### Batch Sizes

- **Small**: 25-50 conditions per run (safe, reliable)
- **Medium**: 50-100 conditions per run (default)
- **Large**: 100+ conditions (only if you have high API quota)

### Cost Estimation

Gemini Flash pricing (as of Dec 2024):

- ~500 tokens per condition (prompt + response)
- ~$0.001 per condition
- 100 conditions ≈ $0.10

## Maintenance

### Monitoring Content Quality

Periodically review generated content:

```bash
# Open Prisma Studio to inspect conditions
npm run db:studio
```

### Updating Prompts

Edit `lib/services/autoAuthor/contentGenerator.ts` to refine AI instructions:

- Adjust clinical focus
- Add specialty-specific requirements
- Modify output structure

### Database Schema Changes

If you add new fields to the `Condition.content` JSONB:

1. Update `GeneratedConditionContent` interface in `types.ts`
2. Update prompt in `contentGenerator.ts`
3. Update merge logic in `databaseService.ts`

## Best Practices

1. **Start Small**: Use `--dry-run` first to see what will be processed
2. **Incremental Runs**: Process 25-50 conditions at a time to catch errors early
3. **Monitor Costs**: Check Gemini API usage dashboard regularly
4. **Review Output**: Spot-check generated content for clinical accuracy
5. **Preserve Manual Edits**: The pipeline never overwrites existing content fields

## Troubleshooting

### No Conditions Found

```
✅ All conditions already have content! Nothing to do.
```

**Cause**: All conditions already have the required fields  
**Solution**: This is normal after initial content generation

### Database Connection Errors

```
❌ Fatal error: Can't reach database server at ...
```

**Solution**:

- Check `DATABASE_URL` in `.env`
- Ensure Supabase/PostgreSQL is running
- Run `npm run db:generate` to sync Prisma client

### Gemini API Errors

```
❌ Generation failed: 401 Unauthorized
```

**Solution**: Verify API key is correct and active
