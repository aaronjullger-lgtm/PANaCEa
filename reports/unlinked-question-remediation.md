## Classification result

All 89 → **manual_review_required**; **0 auto-actionable**.

- No row is degenerate: every row has a full stem, ≥2 options, and a resolvable
  correct answer. Nothing is safe to retire.
- No semantic-hash duplicates; none flagged.
- No subcategory maps to a single confirmed condition concept. Subcategory is a
  *grouping*: it maps to 0 conditions for most (e.g. "Aortic Disease", "COPD",
  "Pneumonia" → 0) or many (e.g. "Acute Coronary Syndrome" → 12, "Heart
  Failure" → 5, "Cardiomyopathy" → 4). A deterministic auto-link would be a
  guess. The only 1-match cases ("Arrhythmias" → `CV__ecg__sinus_arrhythmia`)
  are grouping coincidences, not the concept the vignette tests, so they are
  surfaced for review, never linked.
- The 70 `PreGeneratedQuestion` rows (`q-tax-*`, `q-exp-*`) are well-formed PANCE
  vignettes with raw presentations and no embedded diagnosis name (by design),
  which is exactly why name-matching yields 0 — they are clinically salvageable
  but need a human to assign the precise condition.
- The 19 `Question` rows are `ai-generated`/`manual` items with a system but no
  category/topic and no condition; substantial vignettes, templated stems.

## Action taken

**No database mutation.** There is no high-confidence deterministic link and no
safe retire candidate, so per the sprint's "do not fake clinical judgment" rule
the rows are left for manual linking. They are already excluded from the live
main-study path by `withProgressLinkage()` (commit 3969c9d) and any
previously-served/offline submission still resolves but skips FSRS observably
(`fsrsSkippedReason='missing_condition_linkage'`). No cleanup-apply script was
written because it would have nothing safe to do.
